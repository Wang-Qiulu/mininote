# mininote 版本规格与更新记录

当前版本：**v0.4.0**（2026-11-13，计划中）

这个文件是版本计划与实现的唯一记录。README 只写当前已经实现的功能，不写计划、不列「不做」的清单；计划只写在这里。

---

## 提交流程（每个版本都这么走）

1. **先写计划**：在下面「版本记录」开一节，写清版本号和这一版要做的每一项功能。
2. **先交文档**：只提交本文件，commit 信息写 `docs: vX.Y.Z 版本计划`。
3. **再动手实现**：按这一节列的条目改代码。
4. **本地验收**：本地跑通、自己点一遍，确认每一条都符合计划。
5. **交实现**：commit 信息必须写明是哪个版本的哪个功能，格式 `feat(vX.Y.Z): <功能>` 或 `fix(vX.Y.Z): <功能>`；一条功能一个 commit，不要合并。
6. **每个 commit 都带版本号**，并在本文件对应版本下补一条实现记录（日期 + 做了什么 + commit 号）。

## 版本号规则

- `v主.次.修`：加功能或减功能 → 次版本 +1；只修问题 → 修版本 +1；大改版 → 主版本 +1。
- 升版本时同步改这 5 处：`package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、README 顶部版本徽章。
- 菜单栏里的版本号自动读 `Cargo.toml`，不用手改。

## 版本记录

### v0.4.0 — 2026-11-13（计划中，待实现）

目标：**把「拿到干净的 Markdown 原文」变成一个按钮**，同时**让正文里的一／二／三级标题一眼能分出来**。

原因：现在没有复制功能，想拿笔记内容只能选中编辑器里的字按 ⌘C，拿到的是排版后的文字 —— 列表缩进、待办框、标题符号全被转成一堆空格和空行，粘出去就乱了。另外三级标题虽然各有字号，但只差 1.16／1.08／1.0 倍，在 360px 小窗里肉眼分不出来，看着像统一大小。

需求已在会话里确认，四项都取推荐方案：复制带符号的原文；标题只拉开字号、工具条不动；语法清单只在会话里讲清、App 里不加任何说明入口；「打开笔记目录」直接换掉、不留替代入口。

| # | 功能 | 状态 |
| --- | --- | --- |
| 1 | 顶栏第三个按钮由「打开笔记目录」换成「复制 Markdown 原文」；顶栏仍是三个按钮 + 待办角标，前两个按钮不动 | 待实现 |
| 2 | 点一下把当前笔记**正文的 Markdown 原文**放进剪贴板：`#` `**` `- [ ]` 等符号原样保留；不带 frontmatter，也不带独立的笔记标题输入框 | 待实现 |
| 3 | 复制取编辑器当前状态，不等 400ms 自动保存：刚打完的字、还没落盘的新笔记都能复制到最新内容 | 待实现 |
| 4 | 复制成功按钮短暂显示「已复制」，失败显示「复制失败」，1.6s 后还原；不弹窗、不打断输入、不改动笔记 | 待实现 |
| 5 | 写入剪贴板走 webview 标准接口，失败时回退到临时文本框选中复制；不新增依赖、不新增系统权限 | 待实现 |
| 6 | 拉开三级标题的字号与字重差距，小窗里能明确分出一级／二级／三级 | 待实现 |
| 7 | 支持的语法清单只在会话里说明，App 界面、菜单栏都不加说明入口 | 待实现 |
| 8 | 版本号同步 v0.4.0（5 处），README 补上已实现的复制功能，重新构建 | 待实现 |

**实现方式**：顶栏按钮不在编辑器的组件树里，用一个「取当前 Markdown」的注册点把编辑器的能力交给外壳，避免把编辑器实例塞进全局状态、也避免每敲一个字就重渲染顶栏。剪贴板写入纯前端完成，Rust 侧不动。标题层级只改样式表。

**保持不变**：菜单栏只有版本号 + 退出；双击 ⌘ 仍是唯一快捷键；顶栏前两个按钮（新建笔记、展开/收起列表）与待办角标；标题独立于正文存在 frontmatter 里；自动保存、原子写、外部改动监听与冲突保护；浮出的格式工具条仍只有一个「标题」按钮（一级／三级照旧靠自己打 `#` / `###`）；支持的语法范围不变。

**本版明确不做**：App 内的语法说明或帮助入口；「打开笔记目录」的任何替代入口（Rust 侧 `open_notes_dir` 命令与前端 `api.openNotesDir` 留着但不再调用，不删后端）；表格、图片、高亮、四级及以上标题等新语法；工具条新增分级标题按钮。

**本地验收场景**：
1. 写一条同时含 `#` `##` `###` 标题、粗体、列表、待办的笔记，确认三级标题大小一眼能分。
2. 点顶栏第三个按钮，粘到别的文本编辑器：应是与笔记正文一模一样的 Markdown 原文，没有多余空格和空行，且不含 frontmatter、不含笔记标题。
3. 刚打完字立刻点复制（不等自动保存），内容要包含刚打的字。
4. 新建一条笔记、只打几个字还没切走，点复制能拿到内容。
5. 按钮点完短暂显示「已复制」，约 1.6s 后还原；失败时不弹窗。
6. 展开态（720×300）下点复制，行为与小窗一致。
7. `npm run build`、`npm run test:roundtrip`、`npm run test:escape` 全通过；5 处版本号一致，菜单栏显示 v0.4.0。

### v0.3.0 — 2026-11-12（已验收）

目标：**双击 ⌘ 收起小窗后，焦点回到唤起前正在用的那个应用**，不再让整个屏幕失焦。

原因：唤起时 `set_focus()` 会把焦点抢到小窗（必须，否则打不了字），但 `hide()` 只隐藏窗口、还原浮窗层级，没有告诉系统焦点该交给谁。macOS 对没有 Dock 图标的菜单栏应用不会自动交还。

| # | 功能 | 状态 |
| --- | --- | --- |
| 1 | 唤起前、抢焦点之前，记下当时在前台的应用（排除自己；前台已是自己时保留旧记录） | 已验收 |
| 2 | 收起时把焦点还给它；顺序在隐藏窗口、还原浮窗层级之后 | 已验收 |
| 3 | 收起前确认前台仍是 mininote。用户写笔记中途手动切到别的应用时，不归还、不抢别人的焦点 | 已验收 |
| 4 | 目标应用已退出、或激活失败时静默放弃，最差退回现状，不弹窗报错 | 已验收 |
| 5 | 关键路径加日志（记住了谁 / 是否归还 / 激活结果），便于真机排查 | 已验收 |
| 6 | 版本号同步 v0.3.0，重新构建并装到本机 | 已验收 |

**实现记录**：2026-11-12，commit `ddf40f8` `fix(v0.3.0): 收起小窗后焦点回到唤起前的应用`，本地验收通过。计划文档先由 `323c656` `docs: v0.3.0 版本计划` 单独提交。同一笔实现提交里也带上了此前等验收的 v0.2.0 改动（原因见下）。

**实现方式**：新增 `src-tauri/src/focus.rs`，用 `NSWorkspace.frontmostApplication` 记进程号、用 `NSRunningApplication.activateWithOptions` 归还；改动落在 `window.rs` 的 `show()` / `hide()` 两处。都是普通 AppKit 接口，**不需要新增辅助功能权限**。

**保持不变**：双击 ⌘ 唤起时抢焦点与落光标、全屏 Space 浮窗、启动时不抢焦点、菜单栏菜单、小窗顶栏三个按钮。

**本版不覆盖**：左上红点关闭小窗的路径（不走 `window::hide()`），等以后再定要不要补。

**本地验收场景**：
1. 在浏览器或编辑器里打字 → 双击 ⌘ 写几个字 → 双击 ⌘ 收起，光标应回到原来那个窗口。
2. 原生全屏应用里重复场景 1，确认没有窗口残留、焦点确实回到全屏页面。
3. 小窗打开期间手动点别的应用，再按双击 ⌘ 收起 —— 不能把焦点硬拽回旧应用。
4. 唤起后把原应用退出，再收起 —— 不报错、不闪窗。
5. 连续两次唤起（含再次双击 .app）后收起，仍能正确归还。
